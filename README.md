# MatchFlow OS

Турнирная система: заявки → жеребьёвка → судейство → протокол.
Одна страница, две serverless-функции, хранилище — Redis (Upstash) через REST.

```
index.html        всё приложение: разметка, стили, логика, логотип
api/state.js      GET  — отдать состояние турнира (всем)
                  POST — записать состояние (только судья, заголовок x-judge-pin)
api/register.js   POST — заявка игрока (всем, умеет только добавить себя в заявки)
lib/store.js      чтение/запись в Redis + проверка кода судьи
```

## Как выложить на Vercel

**1. Залить код.** Любой из способов:

- через терминал в этой папке: `npx vercel` (спросит логин, дальше Enter на все вопросы), потом `npx vercel --prod`
- или создать репозиторий на GitHub, закинуть туда эти файлы и на vercel.com нажать **Add New → Project → Import**

**2. Подключить хранилище.** В проекте на Vercel: вкладка **Storage → Create Database → Upstash for Redis** (Marketplace, бесплатный тариф). Нажать **Connect** к проекту. Vercel сам пропишет переменные `KV_REST_API_URL` и `KV_REST_API_TOKEN` — руками ничего вводить не надо.

**3. Поставить код судьи.** Вкладка **Settings → Environment Variables**:

```
JUDGE_PIN = ваш_код
```

Без этой переменной код судьи будет `2604`. Поставьте свой.

**4. Передеплоить** — вкладка Deployments → у последнего деплоя ⋯ → Redeploy. Это нужно, чтобы функции увидели новые переменные.

Всё. Открываете адрес проекта — работает.

## Как это устроено

Состояние турнира — один JSON в Redis: карточка турнира, список игроков, статусы, сетка, лента событий. Каждое действие судьи перезаписывает его целиком и поднимает номер ревизии; остальные вкладки раз в 5 секунд спрашивают «есть ли что-то новее моей ревизии» и подтягивают изменения. Если двое судей нажали одновременно — второй получает 409 и свежую версию, ничего молча не затирается.

Писать состояние может только тот, кто прислал верный `x-judge-pin`. Обычный посетитель через `/api/register` может добавить только одну строчку в список заявок — сетку и результаты этим путём не тронуть.

Если переменные хранилища не заданы, страница честно скажет «локально» и будет работать в одном браузере через localStorage — удобно, чтобы посмотреть интерфейс до настройки Redis.
