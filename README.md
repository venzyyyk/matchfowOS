# MatchFlow OS

Турнирная система: заявки → жеребьёвка → судейство → протокол.
Одна страница, две serverless-функции, хранилище — MongoDB.

```
index.html        всё приложение: разметка, стили, логика, логотип
api/state.js      GET  — отдать состояние турнира (всем)
                  POST — записать состояние (только судья, заголовок x-judge-pin)
api/register.js   POST — заявка игрока (всем, умеет только добавить себя в заявки)
lib/store.js      чтение/запись в MongoDB + проверка кода судьи
```

## Как выложить на Vercel

**1. Залить код.** Любой из способов:

- через терминал в этой папке: `npx vercel`, потом `npx vercel --prod`
- или закинуть файлы в репозиторий на GitHub и на vercel.com нажать **Add New → Project → Import**

**2. Подключить базу.** В проекте на Vercel: **Storage → Create Database → MongoDB Atlas** (Marketplace, бесплатный тариф), затем **Connect** к проекту. Vercel сам пропишет строку подключения в переменные окружения.

Если база заводится не через Vercel, а напрямую в MongoDB Atlas — просто добавьте переменную вручную:

```
MONGODB_URI = mongodb+srv://пользователь:пароль@кластер.mongodb.net/
```

В Atlas при этом нужно разрешить доступ с любого IP (Network Access → 0.0.0.0/0), потому что у serverless-функций адреса плавающие.

**3. Поставить код судьи.** **Settings → Environment Variables**:

```
JUDGE_PIN = ваш_код
```

Без этой переменной код судьи будет `2604` — а он лежит в открытом коде, так что поставьте свой.

**4. Передеплоить** — Deployments → у последнего деплоя ⋯ → Redeploy, чтобы функции увидели переменные.

## Как это устроено

Весь турнир — один документ в коллекции `tournament`: `{ _id: 'state', rev, state, at }`. Внутри `state` лежат карточка турнира, игроки, статусы, сетка и лента событий.

Каждое действие судьи перезаписывает документ целиком и поднимает `rev`. Запись идёт с проверкой ревизии: если в базе она уже больше, чем та, от которой отталкивался клиент, запись отклоняется с 409 и клиент забирает свежую версию — молча ничего не затирается. Остальные вкладки раз в 5 секунд спрашивают «есть ли что-то новее моей ревизии».

Писать состояние может только тот, кто прислал верный `x-judge-pin`. Через `/api/register` посторонний может добавить ровно одну строчку в список заявок — сетку и результаты этим путём не тронуть.

Если переменная с базой не задана, страница честно скажет «локально» и будет работать в одном браузере через localStorage.

Настройки по умолчанию: база `matchflow`, коллекция `tournament`. Меняются переменными `MONGODB_DB` и `MONGODB_COLLECTION`.
