# Групповой этап + OBS overlay

Три новых файла поверх существующего MatchFlow OS. Ничего в `matchflowos.html` и в `api/` не трогалось, всё работает через уже написанный `/api/state` (MongoDB).

## Что добавилось

| Файл | Что делает |
|---|---|
| `lib/groups.js` | Логика round-robin: пары каждый-с-каждым, таблицы с тай-брейками, кто проходит. Работает и в node, и в браузере. |
| `lib/mf-api.js` | Тонкий клиент к `/api/state` (чтение, запись, опрос). Общий для экрана групп и overlay. |
| `groups.html` | Экран группового этапа: создать группы, ввести счёт, увидеть кто проходит, вывести матч на табло. |
| `obs.html` | Overlay для OBS Browser Source. Поллит состояние, показывает текущий матч, меняется в реалтайме за твоим счётом. |

Адреса после деплоя: `твой-домен/groups.html` и `твой-домен/obs.html`.

## Почему раньше "базы не сохранялись"

`matchflowos.html` сохраняется через `claude.use('artifact')`, а без него валится в `localStorage` и в `/api/state` не ходит вообще. Бэкенд на Mongo был написан, но фронт к нему не подключён.

Новые страницы (`groups.html`, `obs.html`) ходят в Mongo напрямую. Чтобы это заработало, на Vercel нужны переменные окружения:

```
MONGODB_URI   = mongodb+srv://user:pass@cluster.mongodb.net/?retryWrites=true&w=majority
JUDGE_PIN     = 2604          # код судьи (тот же, что в сетке)
AUTH_SECRET   = любая_длинная_строка   # для /api/auth, по желанию
```

Vercel → проект → Settings → Environment Variables → добавить → Redeploy.

Без `MONGODB_URI` `/api/state` отвечает `501 no_storage`, и `groups.html` честно скажет, что бэкенд не отвечает.

> Временный Mongo: бесплатный кластер на mongodb.com (Atlas, M0). Создаёшь кластер, жмёшь Connect → Drivers, копируешь строку, подставляешь свой пароль. Позже переедешь на свой хост, поменяв только `MONGODB_URI`.

## Как пользоваться групповым этапом

1. Открываешь `groups.html`, жмёшь **Судейская**, вводишь код судьи.
2. **Сформировать группы**: выбираешь размер группы и сколько человек проходит. Игроки берутся из подтверждённого состава, раскидываются змейкой по рейтингу (группы ровные по силе).
3. В каждой группе играется круг каждый-с-каждым. Жмёшь `+`/`−` на счёте, потом **готово**.
4. Таблица пересчитывается сразу: победы, разница партий, личная встреча. Зелёная линия слева = проходит дальше.
5. Когда все группы сыграны, внизу появляется список прошедших в плей-офф, уже в порядке посева (первые места, потом вторые). Разводишь их по сетке в основном приложении.

Твой пример: Костя / Сеня / Рома в группе. Костя обыграл обоих (2 победы), Сеня обыграл Рому (1 победа), Рома без побед. При "проходят по 2" дальше идут Костя и Сеня, Рома в пролёте. Ровно так и считает.

## Как подключить overlay в OBS

1. OBS → Источники → **+** → **Источник браузера**.
2. URL: `твой-домен/obs.html`
3. Ширина 1920, высота 1080.
4. Галка **Выключить источник, когда он не виден** — снять (чтобы поллинг не вставал).

Табло появляется, только когда ты в `groups.html` нажал на матче **на табло**. Нажал ещё раз — снял. Меняешь счёт на сайте → через ~1.5 секунды меняется на стриме.

Параметры в URL overlay:

| Параметр | Значение | Что делает |
|---|---|---|
| `?bg=green` | | зелёный фон под хромакей (если прозрачность в OBS не берёт) |
| `?size=sm` / `?size=lg` | | меньше / крупнее табло |
| `?mini=0` | | спрятать мини-таблицу группы |
| `?int=1000` | мс | частота обновления (по умолчанию 1500) |

Пример: `obs.html?bg=green&size=lg&int=1000`

## Встроить вкладку групп в основную сетку

`matchflowos.html` — отдельная страница, в неё групповой экран не вшивается. Проще дать ссылку. В разметку шапки (`shell()`, рядом с `.wordmark`) можно добавить:

```html
<a href="/groups.html" class="btn sm" style="text-decoration:none">Группы</a>
```

Строку впиши руками, не копипастой, чтобы не затащить скрытые символы.

## Важно про код

Весь код в файлах перепечатывай руками, а не копируй вслепую: при копипасте из чата иногда цепляются невидимые символы, из-за которых потом ломается то, что по виду должно работать.
